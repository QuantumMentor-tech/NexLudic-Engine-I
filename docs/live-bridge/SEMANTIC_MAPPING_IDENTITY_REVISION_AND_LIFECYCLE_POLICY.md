## 1. Purpose and Scope

This policy governs the unique identification, versioning, classification, approval workflow, and lifecycle transitions of **Semantic Mapping Records (SMRs)**. 

A Semantic Mapping Record defines how data instances conforming to a Source Domain Concept Descriptor are converted into instances conforming to a Target Domain Concept Descriptor (or Canonical Intermediate Representation). This policy ensures that mapping definitions are auditable, tamper-resistant, version-controlled, and strictly verified before activation.

---

## 2. Canonical Identity and Classification

### 2.1 Uniform Resource Name Format
Every Semantic Mapping Record is identified by a canonical URN:
```
map:{source_concept_id}->{target_concept_id}:v{major}.{minor}.{patch}
```
*Example:* `map:ue5_actor_transform->unity_transform_yup:v1.2.0`

### 2.2 Formal Mapping Categories

| Category | Definition | Information Loss | Round-Trip Guarantee | Example |
| :--- | :--- | :--- | :--- | :--- |
| **DIRECT** | 1-to-1 property mapping without value modification or coordinate transform. | Zero | 100% Lossless | Mapping raw player ID string between identical auth backends. |
| **NORMALIZED** | Deterministic mathematical transform (unit scaling, coordinate frame rotation). | Precision-bounded ($\le \epsilon$) | Lossless within floating-point tolerance | Converting Unreal units (cm) to Unity meters (m). |
| **DERIVED** | Target property computed from 2+ source properties via deterministic formula. | Intermediate loss possible | Non-invertible unless inverse formula registered | Computing linear speed scalar from 3D velocity vector. |
| **APPROXIMATE** | Quantization, clamping, or semantic bucket substitution. | Bounded & Disclosed | Lossy (Explicitly Flagged) | Mapping continuous health float `[0.0, 100.0]` to 4-state enum `[CRITICAL, LOW, MED, HIGH]`. |
| **PARTIAL** | Only a subset of source properties can be mapped to target schema. | Residual vaulted | Lossless via `vault_token` | Target game lacks stamina; stamina vaulted for round-trip return. |
| **UNSUPPORTED** | Target domain fundamentally lacks conceptual equivalent. | Absolute | No mapping permitted | Target game has no magic system; spell cast events rejected. |

## 3. Mapping Lifecycle State Machine

```
                   +------------------------+
                   |         DRAFT          |
                   +------------------------+
                               |
                               | Validate Schema & Constraints
                               v
                   +------------------------+
                   |       VALIDATING       |
                   +------------------------+
                        /              \
         Validation    /                \ Validation
           Pass       /                  \ Fail
                     v                    v
          +--------------------+   +--------------------+
          |      APPROVED      |   |      REJECTED      |
          +--------------------+   +--------------------+
                     |                      |
                     | Session Admission    | Terminal
                     v                      v
          +--------------------+         [END]
          |       ACTIVE       |
          +--------------------+
               /             \
    Deprecate /               \ Emergency Revoke
             v                 v
  +--------------------+   +--------------------+
  |     DEPRECATED     |   |      REVOKED       |
  +--------------------+   +--------------------+
             |
             | Superseded by new version
             v
  +--------------------+
  |     SUPERSEDED     |
  +--------------------+
```

### State Definitions and Transition Gates:
1. **DRAFT:** Mapping record authored by developer or generated by proposal tool. Not eligible for session admission.
2. **VALIDATING:** Automated 14-layer verification suite executing static, topological, range, and unit checks.
3. **APPROVED:** Successfully passed all static validation checks and cryptographically signed with developer/admin key.
4. **ACTIVE:** Loaded into an active bridge session engine following capability negotiation (Step 72).
5. **DEPRECATED:** Replaced by newer revision; maintained only for active backward-compatibility sessions.
6. **SUPERSEDED:** All active sessions transitioned to newer revision; record archived as read-only.
7. **REVOKED:** Immediate emergency termination due to detected safety violation, NaN-poisoning, or semantic flaw.

---

## 4. Revision Governance & Immutability

- **No In-Place Modifications:** Once a Semantic Mapping Record reaches `APPROVED` or `ACTIVE` state, its binary representation and `integrity_hash` are frozen. Any modification requires incrementing the semantic version and issuing a new record.
- **Breaking vs Non-Breaking Changes:**
  - Minor version bumps are permitted only if mapping rules preserve backward compatibility and do not increase lossiness.
  - Adding lossiness, changing clamp boundaries, or introducing new derivation formulas requires a Major version increment.
