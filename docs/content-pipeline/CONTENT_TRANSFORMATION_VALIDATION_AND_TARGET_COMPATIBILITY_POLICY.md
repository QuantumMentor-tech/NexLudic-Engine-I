## 1. Overview & Verification Philosophy

A transformed artifact must not be promoted to downstream packaging or installation simply because a file was written to disk. This policy defines the four validation gates of Stage I (Intermediate Artifact Validation) and establishes the target compatibility verification standards.

---

## 2. Four Stage-I Validation Gates

```
[Gate 1: Input Pre-Flight Check]
   Verify source asset SHA-256, format signature, and Gate G4 authorization token.
         |
         v
[Gate 2: Intermediate Schema Conformance]
   Verify canonical IR adheres to glTF 2.0 / OpenEXR schema; coordinate frame normalized.
         |
         v
[Gate 3: Output Structural Binary Validation]
   Verify generated target binary (.uasset, .nif, .dds) passes native adapter parser.
         |
         v
[Gate 4: Semantic & Target Compatibility Verification]
   Verify metric bounds (tolerance <= 0.001), normal vectors, material slots, game build.
```

---

## 3. Metric Invariant & Geometric Verification Standards

When validating transcoded 3D mesh artifacts:
- **Bounding Volume Deviation:** The transformed bounding box extrema must not deviate from the source by more than $\pm 0.001$ units:
  $$\max\left(\|\min(\mathbf{v}_{\text{tgt}}) - \min(\mathbf{v}_{\text{src}})\|_{\infty}, \|\max(\mathbf{v}_{\text{tgt}}) - \max(\mathbf{v}_{\text{src}})\|_{\infty}\right) \le 0.001$$
- **Surface Normal Integrity:** Transformed vertex normals must be unit-length ($\|\mathbf{n}\| = 1.0 \pm 0.001$) and preserve smooth shading topology.
- **Winding Order Consistency:** Front-facing polygon orientation must match the target engine's cull mode without backface inverted rendering.

---

## 4. Target Compatibility Verification & Invalidation

1. **Target Build Alignment:** Output must declare the exact target game build (e.g. `1.6.1170.0`) and modification mechanism (`MOD_DIRECTORY_DROP`).
2. **Invalidation on Host Game Update:** If the target game receives an update, all previously validated outputs must be re-evaluated before deployment.
3. **Independent Verification:** An automated summary generated by an AI coding agent does NOT constitute proof of compatibility without empirical binary parser validation.
